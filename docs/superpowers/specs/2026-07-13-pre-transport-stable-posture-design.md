# 预搬运固定关节稳态设计

## 目标

为 Gensong 双臂移动操作臂定义一个固定的 19 关节预搬运稳态，使以下两条路径最终得到同一个整机关节姿态：

1. 启动 `grasp_waypoint_planner.launch.py` 后的 MPC 初始稳定阶段；
2. 调用 `/continue_return_to_initial_pose` 服务后的放置回程阶段。

现有规划器只发布双臂末端位姿目标。由于机械臂存在冗余，末端位置/姿态相同并不意味着肩、肘、腕关节相同。本设计增加关节空间稳态代价，并继续保留现有末端轨迹约束。

## 固定稳态

稳态使用 `task_dual_ee.info` 的 `initialState.arm` 作为唯一数据源。19 个关节按当前模型顺序排列：底座升降 5 个关节、左臂 7 个关节、右臂 7 个关节。

默认角度（单位：rad）如下：

| 关节 | 目标角度 |
| --- | ---: |
| `leg_low_joint` | 0.05 |
| `leg_up_joint` | 0.10 |
| `waist_low_joint` | 0.00 |
| `waist_up_joint` | 0.00 |
| `chest_joint` | 0.00 |
| `arm1_left_joint` | 0.00 |
| `arm2_left_joint` | 0.05 |
| `arm3_left_joint` | 0.00 |
| `arm4_left_joint` | 0.00 |
| `wrist1_left_joint` | 0.00 |
| `wrist2_left_joint` | 0.00 |
| `wrist3_left_joint` | 0.00 |
| `arm1_right_joint` | 0.00 |
| `arm2_right_joint` | -0.05 |
| `arm3_right_joint` | 0.00 |
| `arm4_right_joint` | 0.00 |
| `wrist1_right_joint` | 0.00 |
| `wrist2_right_joint` | 0.00 |
| `wrist3_right_joint` | 0.00 |

该姿态保持左右对称，躯干和双臂归中，腿部仅离开下限少量以避免限位；URDF 正运动学显示双手高度约为 1.01 m。轮子和手指关节仍按现有 `removeJoints` 处理，不纳入 19 维稳态。

## 方案与选择

### 方案 A：MPC 关节姿态代价（采用）

在 `MobileManipulatorInterface` 中增加一个固定目标关节姿态代价。该代价从 `initialState.arm` 读取目标，并使用 Pinocchio 计算该姿态对应的双末端位姿。

代价仅在当前参考轨迹的末端目标接近固定稳态末端位姿时启用：

- 启动时，硬件 MRT 用固定关节姿态计算初始末端目标，因此代价启用；
- 抓取、抬升、搬运和放置阶段的目标末端不同，代价关闭，不干扰任务轨迹；
- `continue_return_to_initial_pose` 的最终目标改为固定稳态末端位姿，因此代价重新启用并约束 19 个关节。

优点是所有输出仍由 MPC 统一生成，避免额外关节命令源与 MPC 争抢控制权；末端约束和关节姿态约束也能同时生效。

### 方案 B：规划器直接发布关节命令

服务回调直接向硬件关节命令话题发布固定角度。实现简单，但会和硬件 MRT 的 MPC 命令竞争，且绕过 MPC 的速度、碰撞和关节限位处理，不采用。

### 方案 C：只把初始/回程末端目标改成固定姿态

仅根据固定关节姿态计算末端位姿并发布，改动较小，但冗余关节仍由 MPC 自由选择，无法满足“固定 19 个关节角”的要求，不采用。

## 数据流与代码边界

### 配置

- 更新 `task_dual_ee.info` 的 `initialState.arm` 为上述 19 维目标；
- 增加稳态代价参数，包括关节权重、末端稳态激活位置容差、末端稳态激活姿态容差和稳态保持时间；
- 保持硬件 MRT 已有的 `interface_.getInitialState()` 启动路径，使 launch 自动采用同一组关节目标。

### OCS2 接口

新增小型关节稳态代价组件，负责：

- 检查目标向量维度与状态维度；
- 计算当前关节状态相对固定 19 维目标的偏差；
- 仅当参考末端目标接近固定稳态末端时返回非零代价及对应二次近似；
- 通过 `clone()` 支持 OCS2 的代价对象复制。

该组件不修改末端约束的 14 维目标格式，也不改变抓取规划器已有的目标消息接口。

### 规划器

- 启动时从同一 task 文件读取 `initialState.arm`，用 Pinocchio 计算固定稳态的左右末端位姿；
- 不再把第一份 observation 的末端位姿作为最终“initial return”目标；
- `buildInitialReturnWaypoints()` 生成“当前位姿 → 松开后安全退让位姿 → 固定稳态末端位姿 → 固定稳态保持位姿”；
- 服务成功消息明确报告固定预搬运稳态，而不是缓存的任务启动末端位姿；
- 保留现有状态机、碰撞/桌面净空检查和服务状态校验。

## 稳态判定与异常处理

- 19 维目标必须全部为有限值；
- 目标角度必须落在 Pinocchio/URDF 关节限位内，并预留小的限位裕量；
- 如果 task 文件目标维度不为 19，节点启动时立即报错；
- 如果固定姿态计算出的末端位姿含 NaN/Inf，规划器拒绝启动；
- 稳态代价的激活只依据参考末端目标，不依据当前机器人是否已经到位，避免因当前关节偏差而错误关闭代价；
- 回程末端保持时间使用正值校验，确保 MPC 有时间收敛到固定关节姿态。

## 测试与验收

新增或更新以下测试：

1. 稳态配置解析测试：验证 19 维、有限值、对称目标和关节限位校验；
2. 稳态代价测试：目标末端接近稳态时，稳态关节误差为零的代价为零，偏离时产生正确梯度/二次项；
3. 激活门控测试：抓取目标不激活稳态代价，固定稳态目标激活稳态代价；
4. 回程 waypoint 测试：最后两个 waypoint 为固定稳态末端位姿，时间严格递增；
5. Python launch 文件语法检查；
6. `ocs2_mobile_manipulator` 和 `ocs2_mobile_manipulator_ros` 编译及相关 gtest；
7. 可用仿真环境下启动 launch，检查机器人启动后回到固定姿态；完成放置后调用服务，检查 19 个关节角回到同一目标并持续保持。

验收标准是：启动路径和服务回程路径的最终关节状态都以该 19 维向量为目标；仅末端位置相同但关节姿态不同不能视为成功。
